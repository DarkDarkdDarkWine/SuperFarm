## 1. 游戏概述

### 1.1 基本信息
- **原名**: Hodowla Zwierzątek (波兰语,意为"动物饲养")
- **英文名**: Super Farmer / Have You Herd? / Animal Husbandry
- **设计师**: Karol Borsuk (波兰数学家/拓扑学家)
- **首发年份**: 1943年(二战期间华沙)
- **现代出版商**: GRANNA (波兰)
- **玩家人数**: 2-6人 (部分版本2-4人)
- **适合年龄**: 6-7岁以上
- **游戏时长**: 20-45分钟
- **类型**: 骰子/概率/资源管理/财商启蒙

### 1.2 游戏目标
**胜利条件**: 第一个在自己农场中**同时拥有至少1只**以下5种动物的玩家获胜:
1. 兔子 (Rabbit) 🐰
2. 羊 (Sheep) 🐑
3. 猪 (Pig) 🐷
4. 牛 (Cow) 🐄
5. 马 (Horse) 🐴

**注意**: 小狗和大狗是防御道具,**不计入胜利条件**。

## 4. 繁殖机制 (Breeding Mechanism)

### 4.1 核心算法
繁殖基于"配对"原则 - 每2只同类动物可产生1只后代。

**⚠️ 关键规则: 必须"有种才能繁殖"**
- 如果玩家手中**没有**某种动物,骰子投出该动物**不会获得任何东西**
- 唯一例外: 骰子投出**双同动物**(如兔子+兔子),即使玩家没有该动物,也可获得1只
- 这意味着: 开局只有1只兔子,投出猪+牛 → **什么都不获得**

**计算公式:**
```python
def calculate_breeding(player_inventory, dice_result, bank):
    """
    计算繁殖获得的动物
    player_inventory: dict - 玩家当前库存 {动物: 数量}
    dice_result: list - 两颗骰子结果 [动物A, 动物B]
    bank: dict - 公共库存 {动物: 数量}
    
    关键规则: 玩家必须已有该动物,或骰子投出双同动物,才能繁殖
    """
    gains = {}
    
    for animal in ['rabbit', 'sheep', 'pig', 'cow', 'horse']:
        # 计算骰子上该动物的数量
        dice_count = dice_result.count(animal)
        
        # 玩家已有数量
        player_count = player_inventory.get(animal, 0)
        
        # ⚠️ 关键检查: 如果玩家没有该动物,且骰子只投出1个,则跳过
        if player_count == 0 and dice_count < 2:
            continue  # 无法繁殖,跳过
        
        # 总数 = 玩家已有 + 骰子投出
        total = player_count + dice_count
        
        # 配对数 = 总数整除2
        pairs = total // 2
        
        # 实际获得 = min(配对数, 银行剩余)
        actual_gain = min(pairs, bank.get(animal, 0))
        
        if actual_gain > 0:
            gains[animal] = actual_gain
    
    return gains
```

### 4.2 繁殖示例

**示例1: 开局无种不繁殖 ⚠️ 最重要的规则**
- 玩家有: 1只兔子 (开局状态)
- 骰子投出: 猪 + 牛
- 结果: **什么都不获得!**
- 原因: 玩家没有猪也没有牛,单个骰子无法配对

**示例2: 有种才能繁殖**
- 玩家有: 3只兔子
- 骰子投出: 兔子 + 羊
- 兔子: 玩家有兔子 ✓, Total = 3 + 1 = 4, Pairs = 2, 获得**2只兔子**
- 羊: 玩家没有羊 ✗, 单骰无法配对, **不获得羊**

**示例3: 双同动物例外 (从零开始)**
- 玩家有: 0只羊
- 骰子投出: 羊 + 羊 (双羊!)
- 羊: 虽然玩家没有羊,但投出双羊可以配对
- Total = 0 + 2 = 2, Pairs = 1
- 玩家获得**1只羊**

**示例4: 基础繁殖**
- 玩家有: 3只兔子
- 骰子投出: 兔子 + 兔子
- Total = 3 + 2 = 5
- Pairs = floor(5/2) = 2
- 玩家获得**2只兔子**

**示例5: 混合结果**
- 玩家有: 6只兔子 + 1只猪
- 骰子投出: 兔子 + 猪
- 兔子: 玩家有兔子 ✓, Total = 6 + 1 = 7, Pairs = 3, 获得**3只兔子**
- 猪: 玩家有猪 ✓, Total = 1 + 1 = 2, Pairs = 1, 获得**1只猪**

**示例6: 单骰无法配对**
- 玩家有: 6只兔子 + 1只猪
- 骰子投出: 羊 + 猪
- 羊: 玩家没有羊 ✗, 只投出1只羊, **不获得羊**
- 猪: 玩家有猪 ✓, Total = 1 + 1 = 2, Pairs = 1, 获得**1只猪**

**示例5: 库存不足**
- 玩家有4只马
- 骰子投出: 马 + 羊
- 马: Total = 4 + 1 = 5, Pairs = 2
- 但银行只剩**1只马**
- 玩家只能获得**1只马**

**示例6: 投出双猪**
- 玩家有4只兔子 + 2只羊 + 1只马
- 骰子投出: 猪 + 猪
- 玩家没有猪,但投出两只猪可以配对
- 猪: Total = 0 + 2 = 2, Pairs = 1
- 玩家获得**1只猪**

### 4.3 关键规则
1. **⚠️ 无种不繁殖**: 如果玩家没有某种动物,骰子投出单个该动物不会获得任何东西。只有投出**双同动物**才能从零开始获得。
2. **不能凭空获得牛和马**: 由于牛只在骰子B,马只在骰子A,投出"牛+牛"或"马+马"是不可能的。第一只牛或马**必须通过交易获得**。
3. **灾难优先**: 如果同时投出灾难(狐狸/狼)和动物,先处理灾难,再处理繁殖。
4. **库存限制**: 获得的动物不能超过银行剩余数量。

## 5. 灾难机制 (Predator Events)

### 5.1 狐狸 🦊 (Fox)
**触发条件**: 骰子A投出狐狸面

**效果处理 (存在版本差异):**

#### 版本A (官方英文规则PDF):
```python
def fox_attack_v1(player, bank):
    """狐狸吃掉所有兔子"""
    if player.has('small_dog'):
        # 小狗保护,消耗小狗
        bank.return_animal('small_dog', 1)
        player.remove('small_dog', 1)
        # 所有兔子安全
    else:
        # 清空所有兔子
        rabbit_count = player.count('rabbit')
        bank.return_animal('rabbit', rabbit_count)
        player.remove('rabbit', rabbit_count)
```

#### 版本B (知乎/部分中文版本):
```python
def fox_attack_v2(player, bank):
    """狐狸吃到只剩1只兔子"""
    if player.has('small_dog'):
        # 小狗保护,消耗小狗
        bank.return_animal('small_dog', 1)
        player.remove('small_dog', 1)
        # 所有兔子安全
    else:
        # 兔子减少到只剩1只
        rabbit_count = player.count('rabbit')
        lost = rabbit_count - 1  # 保留1只
        if lost > 0:
            bank.return_animal('rabbit', lost)
            player.remove('rabbit', lost)
```

⚠️ **开发建议**: 建议实现为可配置参数,让玩家选择规则版本。

### 5.2 狼 🐺 (Wolf)
**触发条件**: 骰子B投出狼面

**效果处理:**
```python
def wolf_attack(player, bank):
    """狼吃掉除马和小狗外的所有动物"""
    if player.has('big_dog'):
        # 大狗保护,消耗大狗
        bank.return_animal('big_dog', 1)
        player.remove('big_dog', 1)
        # 所有动物安全
    else:
        # 清空: 兔子、羊、猪、牛
        for animal in ['rabbit', 'sheep', 'pig', 'cow']:
            count = player.count(animal)
            if count > 0:
                bank.return_animal(animal, count)
                player.remove(animal, count)
        # 保留: 马、小狗
        # (大狗已经没了,本来就没有)
```

**保留的动物**:
- ✅ 马 (狼不攻击马)
- ✅ 小狗 (狼不吃小狗,但小狗对狼无防御效果)

**被吃掉的动物**:
- ❌ 兔子
- ❌ 羊  
- ❌ 猪
- ❌ 牛

### 5.3 双灾难 (狐狸 + 狼)
如果同一回合投出狐狸和狼:
1. **先结算狐狸** → 失去(所有/大部分)兔子
2. **再结算狼** → 失去羊/猪/牛
3. **最后结算繁殖** (但此时可能已无动物可配对)

### 5.4 重要细节
- 被消耗的狗**归还公共库存**
- 被吃掉的动物**归还公共库存**
- **大狗不能防御狐狸**,只能防御狼
- **小狗不能防御狼**,只能防御狐狸

| 动物 | 等于兔子数 |
|------|-----------|

| 1 牛 | 36 | 6 | 3 | 1 | 1/2 |
| 1 马 | 72 | 12 | 6 | 2 | 1 |

### 6.3 交易规则

1. **时机**: 只能在投骰子**之前**进行
2. **次数**: 每回合**最多一次交易**
3. **方向**: 可以买入也可以卖出(双向交易)
4. **对象**: 
   - 可以与公共库存(银行)交易
   - 可以与其他玩家协商交易(对方可拒绝)
5. **整数约束**: 必须是整数交易(不能换半只动物)
6. **库存约束**: 
   - 玩家必须拥有足够的动物才能卖出
   - 目标库存必须有足够的动物才能买入
7. **禁止讨价还价**: 必须按照汇率表,不允许额外协商

### 6.4 复合交易示例

**示例1: 多换一**
- 玩家有: 6只兔子 + 1只羊 + 2只猪
- 可以一次交易换成: 1只牛
- 计算: 6兔=1羊 → 2羊=1猪 → 3猪=1牛

**示例2: 一换多**
- 玩家有: 1只马
- 可以换成: 1牛 + 2猪 + 2羊
- 计算: 1马=2牛, 取1牛+剩余价值
- 剩余: 36兔子价值 = 3猪 = 2猪+2羊

**示例3: 购买保险**
- 玩家有: 12只兔子
- 可以换: 2只小狗 (12兔=2羊=2小狗)
- 或者换: 1只猪

### 6.5 跨级交易实现代码
```python
# 定义汇率链
EXCHANGE_RATES = {
    ('rabbit', 'sheep'): 6,      # 6兔子 = 1羊
    ('sheep', 'pig'): 2,         # 2羊 = 1猪
    ('pig', 'cow'): 3,           # 3猪 = 1牛
    ('cow', 'horse'): 2,         # 2牛 = 1马
    ('sheep', 'small_dog'): 1,   # 1羊 = 1小狗
    ('cow', 'big_dog'): 1,       # 1牛 = 1大狗
}

ANIMAL_ORDER = ['rabbit', 'sheep', 'pig', 'cow', 'horse']

def get_rabbit_value(animal):
    """获取动物的兔子等价值"""
    values = {
        'rabbit': 1,
        'sheep': 6,
        'pig': 12,
        'cow': 36,
        'horse': 72,
        'small_dog': 6,
        'big_dog': 36,
    }
    return values.get(animal, 0)

def can_exchange(player, from_animals, to_animals, bank):
    """
    检查交易是否合法
    from_animals: dict - 玩家要付出的动物 {动物: 数量}
    to_animals: dict - 玩家想获得的动物 {动物: 数量}
    """
    # 检查玩家库存是否足够
    for animal, count in from_animals.items():
        if player.count(animal) < count:
            return False, "玩家库存不足"
    
    # 检查银行库存是否足够
    for animal, count in to_animals.items():
        if bank.count(animal) < count:
            return False, "银行库存不足"
    
    # 检查等价交换
    from_value = sum(get_rabbit_value(a) * c for a, c in from_animals.items())
    to_value = sum(get_rabbit_value(a) * c for a, c in to_animals.items())
    
    if from_value != to_value:
        return False, f"交易不等价: {from_value} vs {to_value}"
    
    return True, "交易合法"
```

## 7. 游戏初始化 (Game Setup)

### 7.1 设置流程
1. 将所有动物代币放入公共库存(银行)
2. 确定玩家人数(2-6人)和游戏顺序
3. 每位玩家获得自己的农场板(Farm Board)
4. **每位玩家从公共库存获得1只兔子作为起始**
5. 准备好两颗12面骰子
6. 确定第一位玩家(可以是"最近看到过牛的人")
7. 游戏开始

### 7.2 初始状态
```python
def initialize_game(num_players):
```

## 8. 边界条件与特殊情况

### 8.1 库存耗尽
```python
def check_bank_availability(bank, animal, requested):
    """银行库存不足时的处理"""
    available = bank.get(animal, 0)
    if available >= requested:
        return requested
    else:
        # 只能获得剩余的数量
        return available
```

- 当银行某种动物为0时,该动物暂时无法获得
- 只能等待其他玩家通过交易归还或被灾难清空归还
- **权利丧失**: 如果应得4只兔子但银行只有3只,只能得3只,不能"欠"

### 8.2 被狼清空后的情况
- 玩家可能只剩下马和小狗
- 仍可继续游戏
- 可以通过交易卖掉马重新获得其他动物
- 可以等待投出双兔子开始重建

### 8.3 无法行动的情况
- 即使所有动物都被清空,仍可继续投骰子
- 需要投出双同动物才能重新获得起始动物
- 例如: 投出兔子+兔子可获得1只兔子

### 8.4 多人游戏的公平性
- 银行资源是共享且有限的
- 先行动的玩家有优势获取稀缺动物(马/牛)
- 策略: 考虑阻止其他玩家获得关键动物

```javascript
const DICE_A = [

  'cow',                                                       // 1面

];

function rollDice() {
  const diceA = DICE_A[Math.floor(Math.random() * 12)];
```

## 附录B: 状态机定义

```
States:
  WAITING_FOR_TRADE    - 等待玩家决定是否交易
  WAITING_FOR_ROLL     - 等待玩家投骰子
  PROCESSING_PREDATOR  - 处理灾难事件
  PROCESSING_BREEDING  - 处理繁殖
  CHECKING_WIN         - 检查胜利条件
  GAME_OVER            - 游戏结束

Transitions:
  WAITING_FOR_TRADE → (trade/skip) → WAITING_FOR_ROLL
  WAITING_FOR_ROLL → (roll) → PROCESSING_PREDATOR
  PROCESSING_PREDATOR → (done) → PROCESSING_BREEDING
  PROCESSING_BREEDING → (done) → CHECKING_WIN
  CHECKING_WIN → (not_win) → WAITING_FOR_TRADE (next player)
  CHECKING_WIN → (win) → GAME_OVER
```
